## Split local shared-process graph: promising measured reduction

The previously recovered native cycle profiles include V8 parser/preparser/compiler work. Loading the shared process's many local ESM modules offers a bounded loader-overhead hypothesis. This is attribution guidance, not a measurement of retired instructions by module.

The candidate uses esbuild splitting for local modules only, keeps bare packages external, disables minification and tree shaking, and preserves function names. Dynamic imports retain their asynchronous boundaries and shared singleton chunks; existing eager initialization remains eager. The original Root source URL is preserved with a reviewed replacement. The main-process launch path still points to the original shared entry, now a wrapper for the generated graph.

Initial graph: 469 inputs / 157 outputs, 501,206 input bytes / 614,524 generated bytes. Focused execution tests cover lazy initialization, shared state, colliding function names and original Root URLs. Production regression also compares original/bundled execution and package resolution. Whole-bundle AST equality is not asserted for module linking: bundling changes scopes and import paths. The token-compaction experiment retains its exact-token/AST gates unchanged.
